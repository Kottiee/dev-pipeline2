# AI開発パイプライン

AIに開発を依頼し、業務担当者が節目ごとに成果を確認するための仕組みです。
担当者はプログラムの細かな作業を追う必要はありません。スマートフォンまたはPCから、依頼、進捗確認、承認、修正依頼を行います。

## この仕組みでできること

- やりたいこと、必要な条件、守るべき制約を文章で依頼する
- AIが作業を確認しやすい段階に分けて開発する
- 各段階で自動テストとAIレビューの結果を確認する
- 成果に問題がなければ承認し、次へ進める
- 問題があればコメントを付けて修正を依頼する
- 外出先から進捗を確認し、承認待ちの通知を受け取る

成果物そのものをスマートフォン画面で操作する機能はありません。実際の動作確認が必要な場合は、管理者が用意した確認方法を使用してください。

## 基本の流れ

1. 「新規依頼」で目的、要件、制約を入力します。
2. AIが計画、実装、自動テスト、レビューを進めます。
3. 「承認待ち」になったら、テスト結果、レビュー結果、成果物を確認します。
4. 問題がなければ「承認して次へ」、直してほしい場合は「修正を依頼」を選びます。
5. すべての段階を承認すると案件は完了です。

詳しい画面操作は[スマートフォン操作ガイド](docs/mobile-operations.md)、判断基準は[業務仕様](spec.md)、困ったときは[トラブル対応](docs/troubleshooting.md)を参照してください。

## 画面に出てくる言葉

| 表示 | 意味 |
|---|---|
| 案件 | 1つの開発依頼全体 |
| フェーズ | 業務担当者が成果を確認するひと区切り |
| Run | AIが作業した1回分 |
| 機械検証 | テストやビルドなど、決められた方法による自動確認 |
| レビュー | 実装とは別のAIによる問題点の確認 |
| 承認待ち | 業務担当者の判断が必要な状態 |

## 利用開始に必要な準備

通常の利用者は、管理者から案内されたURLをスマートフォンまたはPCで開くだけです。外出先から使う場合は、端末を組織のTailscaleネットワークへ接続します。

管理者が初回セットアップを行う場合は、Python 3.11以上、Git、利用するAIエージェントのCLIと認証が必要です。

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[web]'
dev-pipeline-web --work-dir /絶対パス/work
```

PC内だけで確認するURLは `http://127.0.0.1:8787` です。スマートフォン接続、利用者制限、通知、常時起動の準備は[スマートフォン操作ガイドの管理者向け設定](docs/mobile-operations.md#管理者向け初回設定)にまとめています。

## 利用上の注意

- 自動テストとAIレビューの合格は、業務上の正しさを保証するものではありません。承認前に、実際の利用場面に照らして確認してください。
- 承認操作は取り消し機能を前提としていません。表示中のフェーズと結果を確認してから承認してください。
- 「実行を停止」しても、それまでの作業内容は残ります。再開時は保存済みの状態から続行します。
- スマートフォン画面を閉じても、PC側の処理は継続します。

## AI利用量の表示

案件画面と `dev-pipeline show <案件ID>` には、実行で消費したトークン数を表示します。
CodexとAntigravityでは、各AIサービスの時間枠ごとの割り当て使用率も実行後に収集して併記します。
使用率を取得できない場合も、開発処理そのものは継続します。
